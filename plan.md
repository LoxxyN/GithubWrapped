# GitHub Wrapped — план проекта

## Стек

Next.js (App Router), TypeScript, Tailwind, HeroUI (только лендинг), Framer Motion, react-insta-stories (навигация по слайдам), React Bits (фоны и текстовые анимации), Zod (валидация ответов API), Jest (расчётная логика).

## 1. Страницы

| #   | Страница            | URL                   | Layout                                        |
| --- | ------------------- | --------------------- | --------------------------------------------- |
| 1   | Landing             | `/`                   | Общий layout: шапка + футер                   |
| 2   | Wrapped-презентация | `/wrapped/[username]` | Свой immersive layout, без шапки/футера сайта |

Слайды внутри wrapped — не отдельные страницы, а элементы `stories` в `react-insta-stories`.

## 2. Landing `/`

**Что на странице:**

- Заголовок + короткое объяснение, что это такое (1-2 строки, не абзац)
- Инпут username (HeroUI `Input`) с валидацией допустимых символов GitHub-логина
- Кнопка "Показать мой Wrapped" → редирект на `/wrapped/{username}`
- 2-3 превью-скриншота слайдов для затравки (можно захардкодить на демо-аккаунте)

**Layout:** шапка (лого + ссылка на репозиторий проекта), футер (автор, стек, ссылка на исходники).

## 3. `/wrapped/[username]` — состояния страницы

**Loading:** не спиннер, а этапный статус — "Считаем коммиты… → Смотрим языки… → Ищем streak…" (текст меняется по мере прихода данных с разных эндпоинтов).

**Error:** отдельные сообщения на разные случаи — юзер не найден (404), rate limit исчерпан, пустой аккаунт без контрибьюшенов. Не один общий "что-то пошло не так".

**Успех:** `react-insta-stories` с массивом слайдов, каждый слайд — свой React-компонент.

## 4. Слайды — содержание и визуал

Правило: один тяжёлый анимированный элемент React Bits на слайд (фон **или** текстовая анимация, не оба сразу).

| #   | Слайд                       | Контент                                             | Фон / анимация (React Bits)                                                                      | Акцент                                                |
| --- | --------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------- |

| 2   | Всего коммитов              | Крупное число                                       | Тот же фон, что на слайде 1, для связности                                                       | Счётчик от 0 до N на Framer Motion                    |

## 5. Технические требования

- GitHub-токен только на сервере, запросы к API — через Next.js Route Handler
- Zod-схемы на ответы GraphQL/REST, чтобы отловить неожиданный `null`/отсутствующее поле до попадания в расчётную логику
- Кэш ответа по username в рамках сессии — не долбить API повторно при возврате на ту же страницу
- Расчётные функции (streak, языки, chronotype, активный месяц) — чистые, без сайд-эффектов, тесты на Jest пишутся до UI
- react-insta-stories: свои React-компоненты в `content`, `loop={false}`, отключить автопереход на последнем слайде

## 6. Порядок разработки

1. Route Handler + GraphQL-запрос + Zod-валидация + нормализация данных
2. Расчётные функции + Jest-тесты
3. Landing-страница
4. Механика `react-insta-stories` на моковых данных — проверить навигацию и тайминги
5. Верстка слайдов: подключение React Bits (фон/текст) по одному компоненту на слайд
6. Framer Motion внутри слайдов (счётчики, появление элементов)
7. Подключение реальных данных, loading/error состояния
8. Summary-слайд → рендер в PNG (html-to-image), кнопка "Скачать"/"Поделиться"
9. Деплой на Vercel, README со скриншотами/гифкой

## 7. Визуальные reference и структура слайда

Откуда брать референсы:

Spotify Wrapped — эталон формата "один факт на экран", смотреть именно на композицию и ритм, а не копировать цвета
Готовые клоны формата под GitHub (например Git LookBack) — полезно посмотреть, как решена механика "один факт — один экран" применительно именно к данным разработчика
Dribbble/Behance по запросу "wrapped app" или "year in review" — концепты именно этого формата, смотреть на расположение элементов (где цифра, где подпись, где прогресс-бар)
Background Studio на сайте React Bits — живой конструктор фонов: крутишь настройки, подставляешь свою палитру, сразу видишь результат и экспортируешь готовый код. Это основной инструмент, чтобы не гадать "как будет выглядеть", а увидеть заранее

Структура одного слайда (одинаковая на всех, меняется только контент):

┌─────────────────────────────┐
│ ▬▬▬ ▬▬▬ ▬▬▬ ▬▬▬ │ ← прогресс-бар (react-insta-stories)
│ │
│ │
│ [фон/анимация] │ ← ОДИН тяжёлый элемент React Bits:
│ │ либо анимированный фон,
│ Заголовок │ либо текстовая анимация — не оба сразу
│ Крупное число/факт │ ← Framer Motion (счётчик, появление)
│ Подпись │
│ │
│ │
└─────────────────────────────┘

Порядок работы над визуалом (не придумывать всё заранее):

Собрать все слайды в сером каркасе (как в таблице выше) на реальных данных — проверить, что механика и тексты работают
Только после этого по одному подключать фоны/анимации из Background Studio, сразу глядя на результат в браузере
Не решать "какой фон где" на бумаге до того, как увидел хотя бы один живой пример — визуальные решения в этом формате проще принимать по ходу, а не заранее
